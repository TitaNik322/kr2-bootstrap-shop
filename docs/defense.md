# Подготовка к защите КР №2

## Демонстрация за несколько минут

1. Покажите отдельный репозиторий, README, `main` и историю коммитов/PR. Объясните: КР №2 — новая реализация магазина на Bootstrap, а не изменение стилей КР №1.
2. Откройте главную страницу. В HTML покажите `container → row → col-*`, hero, преимущества и популярные товары. Объясните, почему карточки перестраиваются.
3. Откройте каталог, выберите «Аудио», включите скидку, установите цену до 7000 ₽. Останется Sound Go. Покажите пустые результаты, сброс, сортировку и переход на вторую страницу.
4. Добавьте товар в избранное, откройте его страницу и перезагрузите. Покажите сохранение идентификатора в localStorage. Контактные данные туда не записываются.
5. Откройте разные товары: параметр `id` меняет данные из `js/products.js`. Покажите таблицу характеристик и вкладку доставки. Откройте модальное пояснение, закройте Escape.
6. Нажмите «Оформить заявку». Покажите предвыбранный товар. Отправьте пустую форму: первое ошибочное поле получает фокус, ошибки связаны через `aria-describedby`.
7. Введите вымышленные контакты. Выберите Light Dot, количество 1 и курьера: 2990 + 390 = 3380 ₽. Количество 4: 11 960 ₽, доставка бесплатна. Покажите обязательность адреса.
8. Откройте подтверждение, вернитесь к редактированию, подтвердите заявку. Объясните, что это frontend-демонстрация, отправки на сервер нет.
9. В DevTools переключите 375, 768 и 1440 px. Проверьте меню, карточки, форму и отсутствие горизонтальной прокрутки. Покажите клавиатурный фокус и ссылку перехода к содержимому по первому Tab.
10. В Network покажите локальные CSS/JS/изображения; в исходнике — порядок Bootstrap → custom.css. Покажите README с самостоятельными доработками и результаты тестов.

## Ответы на 20 контрольных вопросов PDF

1. **Что такое CSS-фреймворк?** Набор готовых стилей, правил сетки, utility-классов и компонентов. В этом проекте он задаёт основу страниц, а собственный CSS уточняет оформление.
2. **Почему Bootstrap?** Это основной вариант задания; в одном дистрибутиве есть адаптивная сетка, формы и интерактивные компоненты.
3. **Какие альтернативы допускаются?** Tailwind CSS и Bulma по согласованию, при сохранении требований задания. В данной работе используется Bootstrap.
4. **Для чего `container`?** Ограничивает ширину контента на разных breakpoint и добавляет боковые отступы. `container-fluid` занял бы всю доступную ширину.
5. **Для чего `row`?** Объединяет колонки и управляет межколоночными отступами. Его отрицательные внешние отступы должны компенсироваться контейнером.
6. **Для чего `col-*`?** Задают долю ширины внутри строки, например `col-md-6` занимает половину строки от 768 px.
7. **Что значит 12 колонок?** Ширина строки условно делится на 12 частей: 6/12 — половина, 4/12 — треть. В hero две `col-lg-6` образуют полную строку.
8. **Для чего gutters?** `g-*` задаёт оба отступа, `gx-*` — горизонтальный, `gy-*` — вертикальный. В проекте используется `gx-4 gy-5`; слишком широкий gutter без согласованных отступов контейнера может создавать горизонтальную прокрутку.
9. **Для чего `navbar`?** Готовая адаптивная навигация. Кнопка `navbar-toggler` связана с `#mainNavbar` через `data-bs-target` и ARIA.
10. **Почему меню нужен JS Bundle?** Компонент `collapse` обрабатывает кнопку, раскрытие и состояние `aria-expanded`; CSS задаёт только вид.
11. **Для чего `card`?** Единая структура карточки: изображение, заголовок, текст, цена и действия. В проекте одна функция `card` создаёт одинаковые карточки.
12. **Для чего `badge`?** Компактные метки «Хит», «Новинка», «Скидка» и счётчик избранного.
13. **Для чего `alert`?** Оформляет информационные, ошибочные и успешные состояния. На странице заявки есть пояснение, сводка ошибок и результат.
14. **Для чего `modal`?** Диалог поверх страницы с фокусом и подложкой. В проекте показывает пояснение и проверку данных перед подтверждением заявки.
15. **Какие атрибуты открывают modal?** `data-bs-toggle="modal"` и `data-bs-target="#productHelp"`. В форме окно открывается программно `bootstrap.Modal.getOrCreateInstance(...).show()` после успешной проверки.
16. **Для чего классы полей?** `form-control` — текстовый ввод и textarea, `form-select` — select, `input-group` — поле вместе с префиксом/иконкой, `form-check` — checkbox и radio. Они оформляют поля; правила проверки задаются HTML-атрибутами и JS.
17. **CDN или локально?** CDN загружает библиотеку с внешнего сервера. Локально библиотека хранится с проектом: фиксируется версия и сайт не зависит от доступности CDN.
18. **Какие файлы нужны локально?** `vendor/bootstrap/css/bootstrap.min.css` и `vendor/bootstrap/js/bootstrap.bundle.min.js`. В Bundle включён Popper; отдельно его подключать не нужно. Лицензия сохранена рядом.
19. **Почему custom.css после Bootstrap?** При равной специфичности более позднее правило выигрывает каскад. Здесь точечно задаются цветовые переменные, кнопки, hero, карточки и состояния без замены Bootstrap-сетки.
20. **Какие собственные доработки?** Локальная библиотека; 4 дополнительные страницы; фильтры/сортировка/пагинация; избранное; данные 9 товаров; расчёт суммы и доставки; условный адрес; проверка и подтверждение заявки; tabs, toast, accordion; проверка доступности и адаптивности.

## Где искать реализацию

| Задача | Файл и точка входа |
| --- | --- |
| Данные каталога | `tools/build.py`: `PRODUCTS`; сгенерированный `js/products.js` |
| Единые HTML-компоненты | `tools/build.py`: `nav`, `card`, `faq`, `shell` |
| Избранное | `js/main.js`: `favorites`, `refreshFavorites`, обработчик `storage` |
| Фильтры | `js/main.js`: `renderCatalog` |
| Конкретный товар | `js/main.js`: блок `productContent` и карта `byId` |
| Итог заявки | `js/main.js`: `orderValues`, `updateSummary` |
| Проверка формы | `js/main.js`: `validField`, `markField`, обработчик `submit` |
| Подтверждение | `js/main.js`: `pendingOrder`, `confirmOrder`, `hidden.bs.modal` |
| Собственный дизайн | `css/custom.css`: токены, `.hero`, `.product-card__*`, медиазапросы |

Не заучивайте только названия: измените тестовый товар или правило доставки, пересоберите проект и убедитесь, что понимаете связь данных, DOM, Bootstrap и JavaScript. Преподаватель оценивает и объяснение работы.
